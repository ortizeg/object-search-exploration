Object Search — research-dataset evaluation

Real-dataset run on a vast.ai T4 GPU (bounded sample). Numbers below are a real run over the actual research datasets (RPINE, FSCD-147, FSCD-LVIS), fetched from HuggingFace and evaluated on a rented NVIDIA T4 via scripts/gpu_bench.sh. It is a bounded sample of N=20 images per dataset per split: the full val+test sweep is ~2 days on this hardware because the classical methods (ncc, mosse, sparse-geo) are CPU-bound over the large real images, so treat the metrics as directional, small-sample. Execution provider: the learned dino-dense and propose-retrieve ran on the T4 GPU (CUDA); owlv2-oneshot ran on CPU because owlv2-base at 960px (3600-patch attention) OOMs the T4's 16 GB, so its latency is CPU and much higher. Reproduce or scale up with scripts/gpu_bench.sh. See research-datasets.md for the protocol.

Every method on every external research dataset, at 1 exemplar (the product's one-box operating point) and 3 exemplars (the published-benchmark convention), tuned on val and reported on test. The 3-exemplar numbers are produced by k-shot late fusion — the single-exemplar method is run once per exemplar and the detections are unioned then NMS-deduped in the eval layer, so no method file changed. Abstentions render as n/a, never zero.
