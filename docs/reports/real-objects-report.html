Object Search — real-objects benchmark

The same six methods as the synthetic benchmark, scored on real, segmented object photos pasted onto real background photos — photographic texture, lighting, and JPEG noise no renderer produces, with exact ground truth by construction. See real-objects-findings.md for the synthetic-vs-real comparison and causal analysis. Confidence intervals are bootstrap over images (instances in one image are not independent). Abstentions render as n/a, never zero.

IoU 0.5 · AP all-point interpolation · CPU (deterministic) · git 7fe58e04 · bootstrap 2000× over images

The six methods

Labelled 1–6 as implemented, same numbering as the synthetic report. Each card links its method doc (algorithm, pseudocode, config reference) and a primary reference.

1NCC

Template matching. Correlate the exemplar crop over the whole scene (cv2.matchTemplate, normalized cross-correlation) across an image pyramid; peaks are detections. Zero weights, milliseconds. Best on near-identical, fixed-scale repeats.

method doc →OpenCV template matching →
2sparse-geo

SIFT / SuperPoint keypoints matched many-to-many into the scene (Lowe's ratio test disabled, since it suppresses repeats), then generalized Hough voting in pose space and per-peak RANSAC recover one geometric model per instance. Needs texture; rotation- and scale-invariant.

method doc →Lowe, IJCV 2004 →
3dino-dense

DINOv2 dense patch features for scene and crop; score each scene location by its best-matching-part cosine to the crop tokens (max-token), threshold at a contrast-calibrated cut, connected components with exemplar-relative area bounds. Handles pose/lighting variation; coarse (stride-14) on tiny objects.

method doc →DINOv2, 2023 →
4owlv2-oneshot

OWLv2 image-conditioned one-shot detection. The exemplar crop is encoded as a query image; every scene patch is scored by the cosine similarity of its OWLv2 class embedding to a single query embedding, and accepted patches are read out through OWLv2's own trained detection boxes. One supervised forward pass does localization and matching together -- Apache-2.0, high recall, scale-robust, but lower precision and the slowest method.

method doc →OWLv2, 2023 →
5propose-retrieve

FastSAM proposes class-agnostic regions; each is embedded with the same DINOv2 and matched by cosine nearest-neighbour to the exemplar embedding, then NMS. Boxes hug object boundaries; can over-segment dense grids.

method doc →FastSAM, 2023 →
6MOSSE

The FFT cousin of NCC. A small bank of MOSSE/ASEF correlation filters is synthesized from the warped exemplar (the rotation bank folded into the closed-form solve) and matched by FFT cross-correlation -- a handful of transforms instead of NCC's spatial pass per rotation. Near-NCC F1 on near-identical repeats at ~6x lower latency; weaker in clutter.

method doc →MOSSE, Bolme et al. CVPR 2010 →

The dataset

Real, segmented object photo cutouts pasted onto real background photos, so ground truth stays exact by construction (the pasted alpha mask's AABB) while the pixels themselves carry genuine photographic texture, lighting, and JPEG noise no renderer produces. Full description, provenance, and regeneration commands are in DATASETS.md.

Method, honestly. Ground truth is the AABB of the pasted, warped alpha mask (exact by construction, same rule as the synthetic sets' rotated shapes) — but the mask itself comes from FastSAM automatic segmentation of a real photo, which is not pixel-perfect on every source image (see DATASETS.md's ping-pong-ball caveat). Configs are method defaults, not tuned to these images. Only 10 objects × 3 regimes (30 images) — small enough that per-image variance matters; read the per-regime bootstrap CIs, not just the point estimate.
