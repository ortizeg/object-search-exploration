Per-method verdict

NCC
The honest baseline — and the winner on this data.

Perfect on fixed-scale repeats (recall 0.99), highest F1 (0.92). Zero weights, milliseconds. Collapses when instance scale varies (recall 0.30) and cannot handle rotation without the (default-off) rotation bank. On chipset-04 it found all 15.

sparse-geo
Abstains on this data — correctly.

The chips are low-texture geometric shapes: <20 SIFT keypoints, so the method abstains on 11/12 images rather than fabricate matches. That is the designed guard, not a crash — and its abstention shows as n/a, never a fake zero. It shines on textured natural images, not synthetic chips.

dino-dense
Underperforms here — too coarse for tiny objects.

Stride-14 tokens mean a 24px chip is barely one token; connected components merge into a single blob (found 1 where there are 15). F1 0.12. It is the general-purpose choice for pose/lighting variation on larger objects, which this dataset does not exercise — and it is by far the slowest.

propose-retrieve
The strongest retriever overall.

Best AP (0.635) and recall (0.95); boxes hug object boundaries (SAM proposals). Over-segments here (24 boxes for 15 objects — extra false positives), which post-retrieval NMS only partly tames. Near-flat latency regardless of image size.

Caveats, stated plainly. These scores are on a deliberately NCC-favourable set (identical, axis-aligned, fixed-scale chips) plus a small scale-varied synthetic set — not natural photographs. sparse-geo and dino-dense are built for textured / pose-varying objects this data does not contain, so their low scores here understate them in their intended regime. propose-retrieve over-segments (extra boxes) on dense identical grids. The harness records abstentions and errors as distinct outcomes so none of this is hidden by a pooled average.
