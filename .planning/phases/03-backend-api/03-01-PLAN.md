  <action>
Implement exactly the verified form (PITFALLS §8.2):

  def wilson_interval(successes: int, n: int, confidence: float = 0.95) -> tuple[float,float] | None:
      # raise ValueError on invalid counts
      # n == 0 -> return None  (NOT (0.0, 1.0); [0,1] means "no information")
      # z = NormalDist().inv_cdf(1 - (1-confidence)/2)   -- computed, never hardcoded 1.96
      # centre = (successes + z^2/2)/(n+z^2)
      # half   = (z/(n+z^2)) * sqrt(successes*(n-successes)/n + z^2/4)
      # lo = 0.0 if successes==0 else max(0.0, centre-half)   # max(0.0,...) kills the -0.0 at 0/3
      # hi = 1.0 if successes==n else min(1.0, centre+half)

Tests, all numeric-exact:
- z at 95% == 1.9599639845400534
- 0/10 -> (0.0, 0.2775327998628891); lower is exactly 0.0 (not -0.0)
- 10/10 -> (0.722467200137111, 1.0)
- n=0 -> None
- 0/3 lower bound is 0.0 and not -0.0 (guards the JSON `-0.0` artifact)
- for a spread of inputs, 0 <= lo <= hi <= 1
  </action>

  <name>Task 5: Derived-metric views and the stats query</name>
  <files>src/object_search/store/stats.py, src/object_search/store/schema.py, tests/test_store_stats.py</files>
  <action>
Add SQL VIEWs to schema.py that compute the derived metrics from raw columns (EVAL-07), and a
`scoreboard(conn) -> list[MethodStats]` in stats.py that assembles the per-method board.

The metric semantics (EVAL §7a), with the four SQLite traps handled:
- `FP = COUNT(correct=0 verdicts)` when verdicts_confirmed, else wrong_count, else NULL.
- `TP = retrieved - FP` (NULL-propagating). `FN = missed_count`. `expected = TP + FN`.
- `precision = CAST(TP AS REAL) / retrieved` — **CAST to REAL** (integer division truncates
  0.87 to 0). Undefined (NULL/excluded) when retrieved = 0 (abstention), never 0.
- `recall = CAST(TP AS REAL)/(TP+FN)`.
- Use **SUM**, never TOTAL (TOTAL returns 0.0 where SUM returns NULL — the null-becomes-zero
  bug via a function name).
- Thumbs rate: `n = COUNT(thumbs_up)` **not COUNT(*)** (COUNT(*) counts unrated runs as
  thumbs-down). n_up = SUM(thumbs_up=1).

`MethodStats` (frozen Pydantic) per method: thumbs n and n_up and the Wilson interval on them;
precision with its own n (count of ratings where FP is available); recall with its own n;
p50/p90/p99 latency from the breakdown; abstention count (outcome='empty'); error count
(outcome='error'); threshold-sweep-eligible count (ratings with per-match verdicts). Rank the
board by the Wilson **lower bound** of the thumbs rate, not the raw rate.

Tests:
- Insert runs+ratings covering: a bare thumbs-up (no counts), a full rating, an abstention, an
  error. Assert precision is computed only over runs where FP is available, recall only over
  runs where missed_count is present, and the abstention/error are excluded from precision.
- Assert precision comes back as a real fraction (e.g. 0.75), proving the CAST works.
- Assert the thumbs n excludes unrated runs.
- Assert a method with all-NULL counts yields precision n=0 and a NULL/absent precision, not 0.
  </action>
  <verify>pixi run test tests/test_store_stats.py -v</verify>
  <acceptance_criteria>
    - stats views contain 'CAST(' before every metric division
    - stats views use SUM, not TOTAL
    - a test asserts precision is a real fraction, not 0, for a 3/4 case
    - a test asserts a bare-thumbs run is excluded from precision and recall n
    - the scoreboard ranks by Wilson lower bound
  </acceptance_criteria>
  <done>Derived metrics are query-only and NULL propagates correctly.</done>
