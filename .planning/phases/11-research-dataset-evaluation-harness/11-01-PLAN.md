<objective>
Prove the entire research-dataset architecture end-to-end on ONE dataset (CARPK), and lay down
the fetch / provenance / gitignore contract and the on-disk sidecar+manifest schema that the
other three datasets reuse.

This is the phase's tracer: the thinnest path that touches every layer the phase will modify —
fetch → provenance manifest → native-annotation converter → `*.gt.json` sidecar → split manifest
→ one existing method (`ncc`) through the benchmark at 1 exemplar → a report row carrying the new
literature metrics (P/R/F1 + AP/AP50/AP75 + MAE/RMSE/NAE). Proving this on CARPK first catches an
architectural dead-end after one commit instead of after four converters and a report are already
written.

Why CARPK is the tracer dataset (justification required by the phase brief): it is single-class
(one appearance, "car"), its native annotation is the simplest of the four (one plain-text
bounding-box file per image, `x1 y1 x2 y2 class`), it is **test-only** (D-04) so the tracer does
not also have to prove seeded val-carving in the same task (that is a functionality gap filled in
11-02, not an architectural gap), and it carries the fewest licensing/format surprises. RPINE is
the tightest task fit but its multi-annotator box format and required val-carve make it a poorer
first slice.

D-01..D-11 in this plan refer to the eleven numbered entries under "## Locked Decisions" in
`11-CONTEXT.md` (D-01 = "Four datasets…", D-08 = "Datasets are large and gitignored…", etc.).

Purpose: de-risk the one-way on-disk decisions (datasets/ layout, sidecar+manifest+provenance
format) before mass-fetching, and give 11-02/11-03 a proven seam to expand into.
Output: a fetchable, provenance-recorded, converted, benchmarked, reported CARPK slice plus the
reusable `datasets.py` / `converters/` / `splits.py` / metrics scaffolding.
</objective>

  <name>Task 1: Ratify the one-way on-disk research-dataset contract</name>
  <decision>
    Lock the on-disk layout and schema for research datasets BEFORE any real dataset is fetched
    and converted, because once raw trees, sidecars, and committed manifests exist on multiple
    machines, changing the layout/format is a costly migration (a one-way door). The locked
    decisions D-08 (gitignored datasets/ + fetch-datasets + sha256/source/licence provenance)
    and D-10 (reuse the single *.gt.json loader via converters) fix the intent; this checkpoint
    ratifies the concrete specifics the executor is about to bake in.
  </decision>
  <context>
    Specifics being fixed: (a) raw data path `datasets/<dataset>/…` (gitignored) with a
    human-drop path `datasets/_incoming/<dataset>/` for licence-gated sources; (b) converted
    sidecars co-located as `datasets/<dataset>/<split>/<image_id>.gt.json` in the EXISTING
    GroundTruth schema; (c) an optional additive field `exemplar_indices: tuple[int,...]` on the
    GroundTruth sidecar so FSCD-* native 3-exemplar boxes survive (1-exemplar run = first index);
    (d) committed split manifests OUTSIDE the gitignored tree; (e) provenance at
    `datasets/provenance.json` mirroring `models.py`'s sha256/source/licence discipline.
  </context>
  <options>
    <option id="option-a">
      <name>Committed manifests under conf/datasets/&lt;dataset&gt;.split.json (recommended)</name>
      <pros>Manifests live with the Hydra benchmark config, are committed and diffable, and are
        cleanly separated from the gitignored raw tree — no .gitignore negation needed; CI can
        read them with no fetch.</pros>
      <cons>Split manifest and raw images live in two directories rather than one.</cons>
    </option>
    <option id="option-b">
      <name>Manifests under an un-ignored datasets/manifests/ (negation rule in .gitignore)</name>
      <pros>Everything dataset-related sits under datasets/.</pros>
      <cons>Requires a `!datasets/manifests/` negation, which is fragile next to broad
        `datasets/` ignore; easy to accidentally commit raw data or accidentally ignore a
        manifest.</cons>
    </option>
  </options>
  <resume-signal>Select: option-a or option-b (recommend option-a), and confirm the additive
    `exemplar_indices` sidecar field is acceptable. Then the tracer proceeds.</resume-signal>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external dataset source → local disk | Untrusted archive bytes and file paths cross into the repo during `fetch-datasets` |
| gitignored raw tree → committed repo | Raw images/licence-restricted data must never cross into git history |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Tampering | fetched dataset archive integrity | high | mitigate | `datasets.fetch` verifies sha256 against the DatasetSpec pin (mirrors models.fetch); a mismatch refuses to install and deletes the `.part` |
| T-11-02 | Tampering | archive extraction path traversal (zip-slip) | high | mitigate | reject any member whose resolved path escapes `datasets/<dataset>/` before writing; convert only within the dataset dir |
| T-11-03 | Information disclosure | licence-restricted raw images leaking into git | high | mitigate | `datasets/` gitignored; test asserts `git ls-files datasets/` is empty; provenance records licence per file |
| T-11-04 | Repudiation | which bytes were scored is unclear later | medium | mitigate | `datasets/provenance.json` records sha256 + source_url + licence per file (EVAL-09 discipline) |
| T-11-05 | Denial of service | missing licence-gated archive aborts the sweep | low | accept | graceful-absence path logs the drop instruction and skips, never crashes (mirrors models._export) |
</threat_model>
