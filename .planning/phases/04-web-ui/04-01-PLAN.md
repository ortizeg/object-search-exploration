<task type="auto">
  <name>Task 1: viewport.js — the three-space transform as pure functions</name>
  <files>frontend/js/viewport.js, frontend/dev/selfcheck.html, frontend/dev/selfcheck.js</files>
  <read_first>.planning/phases/04-web-ui/04-CONTEXT.md, .planning/research/PITFALLS.md</read_first>
  <action>
Three coordinate spaces — CSS pixels, backing-store pixels (`cssSize * devicePixelRatio`),
image pixels. Only image pixels may go to the API.

`Viewport` holds `zoom`, `panX`, `panY`, the image natural size, and the canvas element.
Two pure functions that are exact inverses:
  `screenToImage(clientX, clientY) -> {x, y}` (floats)
  `imageToScreen(ix, iy) -> {x, y}`

**The two measured fixes are the point of this task:**
1. Use `event.clientX/clientY` minus `canvas.getBoundingClientRect()`, **NOT
   `event.offsetX/offsetY`** — offsetX is integer-rounded (measured 124 where truth is 123.5),
   and at high zoom that rounding amplifies into a multi-pixel image-space error. Keep every
   intermediate a float; round only at the final integer box conversion.
2. Compute `scaleX = canvas.width / rect.width` and `scaleY = canvas.height / rect.height`
   **separately** — they differ for any canvas whose CSS size ≠ backing store, and one shared
   scalar skews the box (correct in the centre, progressively wrong toward an edge).

Clamp image coordinates to `[0, natural-1]` so a drag past the edge cannot produce a negative
or out-of-range box (the BBox validators would 422).

`frontend/dev/selfcheck.html` + `selfcheck.js` — an in-browser assertion harness (the project
has no JS test runner and adding one means npm). It constructs a Viewport at `dpr=2`,
`zoom=2.3`, a nonzero pan, round-trips a set of known image coordinates through
`imageToScreen` then `screenToImage`, and asserts they return within 0.5px. It renders PASS/FAIL
to the page. This is the reusable proof harness Task referenced below drives.
  </action>
  <verify>Open frontend/dev/selfcheck.html in the browser and confirm PASS (done in Task 4).</verify>
  <acceptance_criteria>
    - viewport.js contains 'getBoundingClientRect' and does NOT contain 'offsetX'
    - viewport.js computes scaleX and scaleY as separate expressions
    - selfcheck.js round-trips coordinates through both transforms and asserts inverse within 0.5px
  </acceptance_criteria>
  <done>The transform is a pair of exact inverses with the two measured fixes in place.</done>
</task>

<task type="auto">
  <name>Task 3: form.js — config form generated from the JSON Schema</name>
  <files>frontend/js/form.js</files>
  <action>
`buildForm(configSchema) -> {element, readValues}` — generates inputs purely from the method's
JSON Schema (UI-07), so a new method needs zero frontend changes. Handle:
  - number with min/max → range or number input
  - integer → number input step 1
  - boolean → checkbox
  - string enum → select
  - array of number → comma-separated text, parsed back to a list on read
`title` → label, `description` → help text, `default` → initial value.
`readValues()` returns a config object matching the schema.

**No method name appears anywhere in `frontend/`** — the form is entirely schema-driven. When
the method `<select>` changes, rebuild the form from that method's schema.
  </action>
