<objective>
Add a textured, richly-annotated benchmark set that exercises the methods the chipset starves:
sparse-geo (needs keypoints) and dino-dense / propose-retrieve (need appearance to vary). Each
instance is a distinct procedurally-textured "emblem" pasted several times with scale, rotation,
and brightness variation, non-overlapping, with exact ground-truth boxes — so precision, recall,
and AP stay computable with no hand-labeling and no licensing.

Purpose: the report is honest that the chipset is NCC-favourable; this set gives the learned and
keypoint methods a fair regime, so the four-method comparison is complete.
Output: a `textured` generator + committed `assets/demo/textured/` set, wired into `/images` and
the benchmark.
</objective>

  <action>
Mirror the chipset module's structure (read `chipset.py` first — reuse its `SyntheticImage`
dataclass, its non-overlap rejection sampler, and its achieved-count discipline).

`TexturedEmblem` — a distinct, richly-textured base patch generated once per image from the seed,
sized `emblem_size`. It MUST be textured enough that SIFT finds **>= 20 keypoints** on it, because
the whole point is to stop sparse-geo abstaining. Build it by layering, in fixed RNG order:
  - a base fill + a low-frequency colour gradient,
  - 4-8 overlapping filled shapes (circles/rects/triangles/polygons) in distinct saturated colours,
  - a few high-contrast thin line/arc accents (these give SIFT its corners),
  - a fine high-frequency speckle/noise field at moderate amplitude (blobs for the detector),
  - an asymmetric mark so orientation is unambiguous (helps rotation recovery).
Keep it deterministic (`cv2.LINE_8`, no antialias; all draws from one `np.random.default_rng`).

`TexturedSpec` (frozen Pydantic): `seed`, `width`, `height`, `n_instances`, `emblem_size`,
`scale_range: tuple[float,float] = (0.6, 1.6)`, `rotation_range_deg: float = 35.0`,
`brightness_jitter: float = 0.25`, `bg: Literal["white","noise","gradient"] = "gradient"`,
`n_distractors: int = 0` (a DIFFERENT emblem, drawn but not in GT — genuine false-positive bait).

`generate_textured(spec) -> SyntheticImage`:
  - Background per `bg` (a mild textured background is more realistic and stresses the methods).
  - Paste the SAME emblem `n_instances` times at non-overlapping positions (rejection sampling
    with a hard attempt cap; **place fewer and record the ACHIEVED count if the cap is hit** —
    never report the requested N). Each paste applies a random scale in `scale_range`, rotation in
    `±rotation_range_deg`, and brightness/contrast jitter within `brightness_jitter` — same object
    identity, varied appearance.
  - Ground-truth box = the **exact AABB of the transformed emblem** (from the warped corners),
    sorted by (y, x). Distractors are pasted but excluded from GT.
  - `slice_metadata`: achieved instance count, observed scale min/max, rotation min/max.
  - Save PNG + `<stem>.gt.json` in the SAME sidecar format as chipset (so `eval/labels.py` loads
    it with no new parser), including an `exemplar_index`.

`TEXTURED_DEMO_SPECS` — a handful of named specs spanning canvas sizes and difficulty:
  `textured-plain` (mild variation), `textured-varied` (full scale+rotation), `textured-cluttered`
  (noise bg + distractors), across a few sizes (e.g. 800x600 → 2048x1536).

Tests (the correctness that makes the set meaningful):
  - **A textured emblem yields >= 20 SIFT keypoints** (`cv2.SIFT_create().detect`) — assert it, so
    sparse-geo has something to match. This is the load-bearing test.
  - Pairwise GT-box IoU == 0 across every image (non-overlap).
  - `len(boxes) == slice_metadata.true_instance_count` (achieved, not requested).
  - Same seed → byte-identical image; different seed differs.
  - Distractors are not in the GT boxes.
  - scale_range and rotation actually vary (observed min != max across instances).

  </acceptance_criteria>
