`match_predictions(pred_boxes, gt_boxes, iou_threshold=0.5) -> (tp, fp, fn)` — greedy IoU
matching, each GT matched at most once (the EVAL-16 convention: two boxes on one instance = 1 TP
+ 1 FP).

`precision_recall_f1(tp, fp, fn) -> (p, r, f1)` — **precision undefined (None) when tp+fp==0**
(abstention), never 0; recall undefined when tp+fn==0.

`average_precision(candidates_with_scores, gt_boxes) -> float` — **all-point interpolation**
(state it in the docstring; note it is the modern COCO-style convention). Compute it from the
**sub-threshold candidate log** (EVAL-08), so a full PR curve — hence AP — comes from a single
operating point's worth of data.

These mirror the store's derived-metric semantics but operate on GT-scored predictions rather
than human ratings; where they overlap, keep the definitions identical.

Tests: R=0 abstention → precision None not 0; a known TP/FP/FN set → exact p/r/f1; an AP case
with a hand-computed all-point value.
  </action>

<task type="auto">
  <name>Task 4: paired comparison + Bradley-Terry with the separation guard</name>
  <files>src/object_search/eval/paired.py, src/object_search/eval/bradley_terry.py, tests/test_bradley_terry.py</files>
  <action>
`paired.py` — `run_paired(image_id, exemplar, configs) -> PairedResult` runs the **same box**
through all four methods in one call (EVAL-05), scores each against GT where available, and
records win/loss/tie per method pair into the `paired_comparisons` table.

`bradley_terry.py` (PITFALLS §8.3, all three layers):
  - `strongly_connected(wins, methods) -> bool` — reachability from each node, iterating
    `sorted(...)` for determinism. If False, refuse to report absolute strengths / flag the
    ranking regularised-only, and always surface the per-pair comparison count.
  - **Regularise with pseudo-games**: add `EPS` wins *and* `EPS` losses to every ordered pair
    (`EPS = 0.5`, a reported config knob). This guarantees strong connectivity and shrinks
    differences toward zero.
  - **Pin the scale** — BT is identified only up to an additive constant on β; normalise to
    geometric-mean-1 on the strengths (or fix one method at β=0), or successive fits are
    incomparable.
  - **Ties are a distinct outcome** kept in the DB (half a win each is the pragmatic scoring);
    the distinction must survive so the choice can be revisited.
  - Report the ranking **with uncertainty**, not as a bare ordering.

Tests:
- **An undefeated method yields a FINITE score** (the complete-separation guard) — construct a
  win graph where method D never loses and assert the fit returns finite strengths.
- `strongly_connected` returns False on a disconnected graph and True after regularisation.
- Scale-pinning: two fits of the same data return comparable (equal up to tolerance) strengths.
  </action>
  <verify>pixi run test tests/test_bradley_terry.py -v</verify>

    - strongly_connected detects a disconnected win graph

  </acceptance_criteria>
