<task type="auto">
  <name>Task 2: Marker reference-point and orientation estimation</name>
  <files>src/object_search/explorations/markers.py, src/object_search/explorations/__init__.py, tests/test_markers.py</files>
  <action>
`markers.py` — the one genuinely new CV piece.

`MarkerGeometry` (frozen): `reference_point: Point`, `direction: tuple[float,float] | None`,
`confidence: float`.

`estimate_geometry(crop, box, transform=None, exemplar_tip=None) -> MarkerGeometry`:
  - **If `transform` is provided** (the marker-finding method fitted a per-instance 2×3 affine,
    row-major `[a,b,tx,c,d,ty]`): rotation `theta = atan2(c, a)`; direction = `(cos theta, sin theta)`.
    Resolve the 180° flip by mapping the exemplar marker's own tip through the transform and
    orienting the direction from centroid toward that mapped tip. Reference point = the mapped tip.
  - **Else** (no transform): threshold the crop to a foreground mask; **PCA on the foreground pixel
    coordinates** gives the principal axis. Resolve the tip via the **arrowhead-mass heuristic**:
    split the mask at the centroid along the principal axis; the end with the smaller
    perpendicular-width profile (the narrowing arrowhead) is the tip; direction = centroid→tip.
    Set `confidence` from the mass asymmetry.
  - **Symmetric / low-confidence:** if the two ends are within a tolerance (a dot, a plus, a blob),
    return the **centroid and direction=None** — never a guessed direction. Record it.

Tests (exact GT from Task 1 synthetic arrows):
  - PCA path recovers each synthetic arrow's direction within ~10° and the tip within a few px.
  - A dot returns direction None.
  - The transform path: build a known 2×3 rotation affine, assert the recovered theta matches and
    the flip is resolved toward the exemplar tip.
  - Determinism: same input → identical geometry.
  </action>

    - a symmetric marker returns direction None

  </acceptance_criteria>

<task type="auto">
  <name>Task 4: The marker-conditioned exploration</name>
  <files>src/object_search/explorations/marker_conditioned.py, src/object_search/explorations/__init__.py, tests/test_marker_conditioned.py</files>
  <read_first>src/object_search/explorations/markers.py, src/object_search/search/proposals.py</read_first>
  <action>
One self-contained module, numbered step comments matching `docs/explorations/marker-conditioned.md`
(written in 09-02), a ROBUSTNESS BACKLOG docstring section, explicit pre/post-processing.

`MarkerConditionedConfig` (frozen, every field Field-described): `marker_method: str = "sparse-geo"`,
`marker_config: Mapping[str, object] = {}` (validated against the chosen method's config_model),
`proposal: FastSAMConfig = FastSAMConfig()`, `w_distance=1.0`, `w_direction=0.5`,
`w_objectness=0.5`, `w_size=0.3`, `size_prior_frac=2.0`, `max_markers=20`, `seed=0`.

`@register_exploration(name="marker-conditioned", ...)` on `run(image, marker_exemplar, config) -> SearchResult`:
  # 1. Find markers: `get_method(config.marker_method).search(image, marker_exemplar, cfg)`; take
       up to max_markers matches. If none, return outcome=EMPTY with a note (never silent).
  # 2. Per marker: `estimate_geometry(crop, box, transform=match.transform, exemplar_tip=...)`.
  # 3. `proposals = propose(image, config.proposal)` — **once** for the whole image.
  # 4. Per marker, score every proposal:
       `score = w_distance*proximity + w_direction*alignment + w_objectness*obj + w_size*size_fit`
       where proximity decays with distance from the reference point, alignment is the cosine
       between the marker direction and (proposal_center - reference_point) (skipped/zero-weighted
       when direction is None), size_fit compares proposal size to `size_prior_frac * marker_size`.
       Pick the best proposal per marker; assemble as a `Match` (score = the marker's best score).
  # 5. Diagnostics: `proposals` (all, for the overlay), plus `metrics` (n_markers, n_proposals) and
       `notes`; also stash per-marker reference points + directions so the UI can draw the arrows.
       Latency attributes find-markers vs propose separately. Register; add the import to __init__.

METHOD-12 analogue: return one best proposal PER marker — never collapse to a single global result.

Tests (model-free via a stub proposal backend + injected marker matches, plus a skip-when-absent
end-to-end): with 3 synthetic markers and a stub proposal set, assert 3 matches, each the nearest
well-aligned proposal; a marker with direction None still scores by distance/objectness; no markers
→ outcome EMPTY with a note; determinism under a fixed seed.
