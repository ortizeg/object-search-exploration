**This file is read directly by an ML practitioner. Readability outranks DRY. Numbered step
comments must match the headings in `docs/methods/ncc.md`.**

Module docstring carries, in this order: what the method does, the **explicit pre-processing**
(grayscale vs colour, dtype, any normalization), the **explicit post-processing** (how a response
peak becomes a box), the known failure modes, and a `ROBUSTNESS BACKLOG` section.

`NCCConfig` — frozen Pydantic, per 02-CONTEXT.md:
`scales`, `angles_deg=(0.0,)`, `threshold: float | None`, `calibration`, `peaks`, `nms_iou`,
`suppression_radius_frac`, `max_candidates=50`, `seed=0`, `retain_frac`.
Every field needs a `Field(description=...)` — the description becomes the UI form help text via
the JSON Schema, so this is the one place it must be written.

`@register_method(name="ncc", description=..., version="1.0.0", config_model=NCCConfig)`
on a module-level `def search(image, exemplar, config) -> SearchResult`.

Numbered steps:

  # 1. Crop the exemplar and guard against a textureless template
  Compute the crop's standard deviation FIRST. If below epsilon (~1e-6), return
  `outcome=EMPTY` with a `Diagnostics.notes` entry explaining that `TM_CCOEFF_NORMED` is
  undefined for a zero-variance template.
  **This guard is mandatory, and the reason is measured, not theoretical:** research found
  OpenCV 4.x returns `1.0` at *every pixel* for a flat template and 5.x returns `0.0` — neither
  raises and neither yields NaN. Without the guard, a textureless crop produces a confident wall
  of false positives. Pin the observed behaviour in a test so an OpenCV bump is caught.

  # 2. Build the scale pyramid
  **Rescale the SCENE, and crop the template from the DOWNSCALED scene.** This reverses the
  intuitive approach and the reversal is measured: downscaling the template independently drops
  the exemplar's own self-match from 1.0000 to 0.3071, non-monotonically, so it cannot be
  corrected by an offset. Cropping from the already-downscaled scene keeps it at 1.0000.
  Comment this explicitly — it looks wrong to a reader who has not seen the measurement.

  # 3. Optionally build the rotated-template bank
  Default `angles_deg=(0.0,)` — off, because it is a large constant-factor cost.
  When enabled, rotating a crop leaves empty corners whose zeros bias the correlation. Either use
  a rotated mask with `cv2.matchTemplate`'s mask argument, or inscribe the largest axis-aligned
  rectangle in the rotated crop. State which was chosen and why in the docstring.

  # 4. Correlate over the FULL scene at every level
  `cv2.matchTemplate(scene_level, template_level, cv2.TM_CCOEFF_NORMED)`.
  **Never crop the search region.** Research measured that restricting the search extent changes
  ~73% of the returned floats and shifts the peak from 0.99999994 to 1.0 — the single biggest
  threat to "same input ⇒ identical results". If a search restriction is ever added it must join
  the config and therefore the config hash.
  Replace any NaN in the response with `-inf` before peak finding, or the argmax may return it.

  # 5. Extract peaks per level
  Use `common.peaks.extract_peaks` with the configured strategy, `template_w/h` at that level.
  **Cross-level comparison is biased** — the spurious noise floor varies ~15× with template size
  (0.577 at 8×8 vs 0.039 at 128×128), so a naive argmax across levels favours the smallest
  template. Normalize each level's scores against that level's own distribution (e.g. z-score
  against the level's median/MAD) before pooling across levels, and record in the docstring that
  the bias is why. Keep the level index per peak so the output box size is right.

  # 6. Map peaks to boxes
  `matchTemplate` output is `(H-h+1, W-w+1)` and each value is anchored at the template's
  **top-left**, not its centre. At level scale `s`, the box in original-image coordinates is
  `BBox(x=round(px/s), y=round(py/s), w=round(tw/s), h=round(th/s))`. No centre offset. Getting
  this wrong shifts every box by half a template, which reads as "slightly bad matching" rather
  than a bug.

  # 7. Calibrate the threshold
  `common.calibration.calibrate` with the configured strategy, passing the exemplar self-match
  score for `self-similarity`. If `config.threshold` is set, use `"fixed"`.

  # 8. Split into matches and sub-threshold candidates
  Keep the top `max_candidates` peaks as `Candidate` objects **with raw scores**, regardless of
  threshold (EVAL-08 — this is what makes an offline threshold sweep possible later). Those above
  the threshold become `Match` objects. Run final cross-level NMS over the accepted matches.
  Label the peak that coincides with the exemplar box (high IoU) as `is_exemplar=True` rather
  than dropping it or counting it twice.

  # 9. Assemble diagnostics and the result
  `Diagnostics` with the heatmap (via `viz.heatmap_png_b64` of the level-1.0 response), and
  `metrics` carrying crop std, per-level peak counts, the chosen threshold, and the calibration
  reason. `LatencyBreakdown` timed around preprocess / matchTemplate / postprocess.

  **METHOD-12: never short-circuit to a single best match.** No `minMaxLoc`-only path. A test
  must assert that a lattice of N instances returns N matches, not 1.

`search/__init__.py` — add `from object_search.search import ncc  # noqa: F401` with the comment
explaining this import exists purely for the registration side effect. That plus the new file is
