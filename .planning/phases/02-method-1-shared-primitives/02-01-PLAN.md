  <files>src/object_search/search/common/nms.py, tests/test_nms.py</files>
  <action>
`nms(boxes: Sequence[BBox], scores: Sequence[float], iou_threshold: float) -> list[int]`
returning the KEPT INDICES (not the boxes), so a caller can carry its own per-box payload
through without this module needing to know about it.

**Deterministic tie-breaking is the whole point of putting this in a shared module.** Sort by
`(-score, box.y, box.x)`. Sorting by score alone leaves equal-scoring boxes in whatever order
the caller happened to build them, which on a symmetric synthetic lattice means the output
changes between runs and breaks the reproducibility constraint. Document that reason inline.

Use `BBox.iou` from the Phase 1 schemas. Plain greedy loop — no vectorization; this runs on tens
of boxes and readability matters more.

Tests: a clear-cut suppression case; an exact-tie case run twice asserting identical output; an
empty-input case; and a case where two boxes have IoU exactly at the threshold (assert the
documented boundary behaviour, `>` vs `>=`, and state which it is).
  </action>

<task type="auto">
  <name>Task 2: peaks.py — nms / local-max / watershed</name>
  <files>src/object_search/search/common/peaks.py, tests/test_peaks.py</files>
  <action>
`Peak` — frozen: `x: int`, `y: int`, `score: float`.

`extract_peaks(response, *, strategy, template_w, template_h, floor, max_peaks, suppression_radius_frac=0.5) -> list[Peak]`

`response` is the float32 correlation/similarity map. `template_w/h` are the exemplar crop
dimensions **at the response map's scale** — needed because the suppression radius is derived
from them, which is what makes `local-max` size-aware instead of using a magic pixel count.

Three strategies, dispatched by a small `if/elif` at the top of the function (NOT a class
hierarchy or a registry — this is a leaf utility and must stay readable):

- `"nms"` — take every location above `floor`, build boxes of template size, run `nms.nms`.
  This is the baseline that *merges touching instances*, and it exists precisely so the failure
  is demonstrable.
- `"local-max"` (default) — `scipy.ndimage.maximum_filter` with a footprint of
  `(round(template_h * frac), round(template_w * frac))`, keep points where
  `response == filtered` and `response > floor`. Then drop duplicates within the radius,
  breaking ties by `(-score, y, x)`.
  Guard the footprint to be at least 3×3 and odd, or `maximum_filter` behaves surprisingly on
  even sizes.
- `"watershed"` — threshold at `floor`, distance-transform, find markers via local maxima of the
  distance map, run `cv2.watershed` (or `scipy.ndimage.label` on the marker set), and emit one
  peak per labelled region at that region's argmax. **Skip label 0** — research flagged that
  `connectedComponentsWithStats` label 0 is the background and emitting it produces a
  full-image false positive. The same hazard applies to any labelling here.

Sort the final list by `(-score, y, x)` and truncate to `max_peaks`.

Tests:
- **The load-bearing test:** build a synthetic response map with two Gaussian bumps whose
  template-sized boxes overlap enough for plain NMS to merge them, and assert
  `len(local-max peaks) == 2` while `len(nms peaks) == 1`. This is Phase 2 success criterion 2.
- A single-bump map returns exactly one peak under all three strategies.
- An all-below-floor map returns an empty list under all three.
- Determinism: a perfectly symmetric two-bump map returns the same order twice.
  </action>
  <verify>pixi run test tests/test_peaks.py -v</verify>
  <acceptance_criteria>
    - peaks.py contains 'maximum_filter'
    - A test asserts local-max finds 2 peaks where nms finds 1 on the same touching-bump map
    - Any labelling path explicitly skips label 0 with a comment saying why
    - Final sort key includes y and x
  </acceptance_criteria>
  <done>The touching-instance separation test passes, proving local-max beats nms.</done>
</task>

<task type="auto">
  <name>Task 3: calibration.py — self-similarity / ratio / gmm</name>
  <files>src/object_search/search/common/calibration.py, tests/test_calibration.py</files>
  <action>
`CalibrationResult` — frozen: `threshold: float`, `strategy: str`, `reason: str`,
`degenerate: bool = False`. The `reason` field is what makes Phase 2 success criterion 4
("different, **inspectable** thresholds") actually checkable — a bare float is not inspectable.

`calibrate(scores, *, strategy, self_score=None, seed=0, ...) -> CalibrationResult`

- `"fixed"` — passthrough of an explicit threshold (so `ncc` has one code path).
- `"self-similarity"` — calibrate relative to the exemplar's own self-match score. The exemplar
  correlated against itself scores ~1.0 for NCC; a match is accepted above
  `self_score * retain_frac`. Requires `self_score`; raise a clear `ValueError` naming the
  strategy if it is missing rather than silently defaulting.
- `"ratio"` — sort descending, find the largest relative gap between consecutive scores within
  the top-N, and cut there. Report the gap in `reason`.
- `"gmm"` — `sklearn.mixture.GaussianMixture(n_components=2, random_state=seed)` on the score
  distribution reshaped to `(-1, 1)`. Threshold is the crossing point between the two component
  means (bisect on the posterior, or take the midpoint weighted by the component stds).
  **Degeneracy guard (required):** if the two component means are closer than a fraction of the
  pooled std, or either weight is below a floor, the two-mode assumption does not hold. Set
  `degenerate=True`, fall back to the `ratio` strategy, and say so in `reason`. Returning a
  confident-looking threshold from a single-mode distribution is worse than admitting it.
  `random_state=seed` is a **real** seed here — GMM initialization genuinely is stochastic,
  unlike OpenCV's RANSAC.

Tests:
- A clearly bimodal distribution: all three strategies return a threshold that separates the
  modes, and the three thresholds are not all equal.
- A unimodal distribution: `gmm` sets `degenerate=True` and its `reason` mentions the fallback.
- `self-similarity` without `self_score` raises ValueError.
- `gmm` with the same seed twice returns the identical threshold.
  </action>
  <verify>pixi run test tests/test_calibration.py -v</verify>
  <acceptance_criteria>
    - CalibrationResult carries a 'reason' string field
    - calibration.py contains 'random_state=' fed from the seed argument
    - A test asserts degenerate=True on a unimodal distribution
    - A test asserts the three strategies do not all return the same threshold on a bimodal input
  </acceptance_criteria>
  <done>All calibration tests pass including the degeneracy fallback.</done>
