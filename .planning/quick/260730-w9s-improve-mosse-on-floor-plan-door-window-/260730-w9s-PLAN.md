<objective>
Improve `mosse` on the floor-plan door/window domain (Roboflow floor-plans-500), NOT the synthetic
chipset/textured regimes already tuned in `docs/reports/mosse-improvement.md` (must not regress --
mosse currently beats `ncc` on VARIED/CLUTTERED there via its coarse-to-fine verify step).

A real target-domain eval (`docs/eval/floorplans-findings.md`) measured, on the 28-plan test split:
`mosse` doors F1 0.213, recall by symbol size (small/med/large) 0.19/0.25/0.36. This is LESS flat
than `ncc`'s pattern (0.31/0.31/0.29) -- mosse's recall does climb somewhat with size -- so this
task verifies the shared hypothesis independently for mosse rather than assuming ncc's finding
transfers unchanged.

**Leading hypothesis, NOT yet verified -- verify empirically, don't assume it's right:**
`MOSSEConfig.train_angles_deg` (mosse.py L221-229) defaults to a 7-step bank over +/-35 deg, folded
via `_angle_groups`/`_build_filter_bank` (L424-522, default `n_angle_groups=3`) into 3 sharp
sub-filters. A door on a perpendicular wall can be ~90 deg off the exemplar -- outside the bank.
Door swing (mirror) is uncovered by any rotation bank. mosse has TWO mirror-relevant sites that may
need addressing: (a) `_build_filter`'s training warp (L472-478, only `cv2.getRotationMatrix2D`, no
flip) and (b) `_rotated_template_bank`'s warp for the coarse-to-fine verify re-score (L626-659, same
rotate-only pattern, invoked from `_verify_score` L662-713 via `config.train_angles_deg` at the
L895 call site). Since `verify=True` is the default and its local NCC re-score drives the accept
threshold, test whether flip coverage in the VERIFY step ALONE (cheaper -- a local re-score, not
full filter retraining) is sufficient before assuming the filter-training side also needs it.

**A sharp trap to avoid:** naively widening `train_angles_deg` to ~28 angles (4 cardinals x the
existing +/-35 sub-bank) while leaving `n_angle_groups` at its default of 3 gives sub-filters
trained on ~9-10 angles spanning ~70 deg each -- which IS the already-measured-bad
`n_angle_groups=1` "one blurry filter" case (VARIED F1 0.267 per the existing report's own
findings). The invariant to hold is roughly 2-3 angles PER sub-filter, so 28 angles needs on the
order of 10-12 groups, not 4. A literal reading of "widen the bank" without also scaling groups
would measure a regression and wrongly refute the hypothesis -- do not make that mistake.

**What NOT to blame:** `mosse` already correlates at native pixel resolution over the FULL scene
via FFT (no resize/letterbox bottleneck -- that's a different, already-documented issue for
`dino-dense`/`owlv2`). Scene tiling is a fallback lever only, tested last if steps 2-3 don't close
the gap.

Purpose: turn an untested hypothesis into a measured verdict for mosse specifically, ship whatever
change actually earns its keep on the floor-plan domain without touching the synthetic-regime
numbers, and write up the finding (compared against ncc's parallel finding) for the next reader.
Output: a (possibly empty) code change gated by measurement, a dated report section, and a clean
commit trail ready for its own PR.
</objective>
