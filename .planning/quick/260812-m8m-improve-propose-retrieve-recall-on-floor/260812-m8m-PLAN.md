<objective>
Improve `propose-retrieve` recall on the **floorplans-door** target domain via a 3-step ablation
(2 committed steps + 1 conditional), each measured and each kept only if it earns its place.

**The root cause is already diagnosed empirically this session** (not a hypothesis to re-test from
zero -- but it MUST be re-derived by committed code before it appears in a report). Splitting
FastSAM proposal-stage recall from final recall across all 84 `floorplans-door` val+test plans:

| doors/plan (crowding bucket) | mean n_proposals | proposal recall | final recall |
|---|---|---|---|
| 1-3 (sparse) | 42 | 0.74 | 0.57 |
| 4-10 | 47 | 0.51 | 0.44 |
| 11+ (crowded) | 60 | 0.27 | 0.23 |

Two independent proposal-stage failure modes:

1. **Fixed proposal budget.** FastSAM's everything-mode proposal COUNT barely scales with true
   instance count (42 -> 47 -> 60, 1.4x) while true door count grows 7x (2.1 -> 6.9 -> 14.7 mean).
   FastSAM carries a natural-photo "typical object count" prior. Worst case: a plan with n_gt=28
   got 37 proposals -> recall 0.07.
2. **Fixed 1024 letterbox.** `FASTSAM_INPUT_SIZE = 1024` regardless of source resolution. One
   4000x1685 plan with 18 doors was downscaled ~4x; of its 83 proposals, ZERO overlapped a door
   (proposal recall 0.00).

Final recall tracks proposal recall in every bucket (a roughly constant ~15-20% relative loss), so
the DINOv2 embedding + gmm/similarity_floor calibration stage is comparatively healthy and is **not**
the primary leak. This ablation targets the PROPOSAL stage.

**Step 1 (committed):** SAHI-style tiled FastSAM proposals. Attacks both failure modes at once --
tiling multiplies the effective proposal budget in proportion to plan area, and each tile is a
smaller crop so a small door is no longer shrunk by the fixed 1024 letterbox before detection.
**Step 2 (committed):** on top of step 1, sweep `proposal_conf` (default 0.4).
**Step 3 (conditional):** only if steps 1+2 miss an explicit, pre-stated VAL criterion -- a second
`ProposalBackend` that scales with instance density instead of carrying FastSAM's object-count prior.

Baseline to beat (`docs/eval/floorplans-findings.md`, floorplans-door TEST, 28 plans, 1 exemplar,
tuned-on-val): **F1 0.459, precision 0.55, recall 0.39, coverage 13/14**. Recall by symbol size
0.34 / 0.42 / 0.36 (small/medium/large).

Purpose: convert a confirmed proposal-stage diagnosis into a measured, shipped improvement (or an
honest measured-and-reverted record), without regressing floorplans-window or the four
chipset/textured/synthetic regimes recorded in `docs/reports/propose-retrieve-improvement.md`.
Output: a measurement-gated code change, a lab notebook, a dated engineering report, an updated
findings table, and a clean atomic commit trail ready for its own PR.
</objective>
