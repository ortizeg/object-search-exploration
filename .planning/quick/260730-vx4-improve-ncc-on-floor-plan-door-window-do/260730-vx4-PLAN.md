<objective>
Improve `ncc` on the floor-plan door/window domain (Roboflow floor-plans-500), NOT the synthetic
chipset/textured regimes already tuned in `docs/reports/ncc-improvement.md` (must not regress).

A real target-domain eval (`docs/eval/floorplans-findings.md`) measured, on the 28-plan test split:
`ncc` doors F1 0.248, recall by symbol size (small/med/large) 0.31/0.31/0.29 -- flat and low, the
signature of an orientation/pose problem rather than a scale/texture one (recall should climb with
symbol size if it were the latter; it largely doesn't).

**Leading hypothesis, NOT yet verified -- verify empirically, don't assume it's right:**
`NCCConfig.angles_deg` (ncc.py L168) defaults to a 7-step bank over only +/-35 deg. A door on a
floor plan sits on whichever wall it's drawn on, so an instance on a perpendicular wall can be ~90
deg off the exemplar -- entirely outside the bank. Separately, door SWING direction (left- vs
right-hand hinge) is a MIRROR of the exemplar that no rotation bank, however wide, will ever cover;
`cv2.matchTemplate` needs an explicitly flipped template for that. `_rotated_bank()` (ncc.py ~L253)
currently only warps by rotation angle via `cv2.getRotationMatrix2D` -- there is no flip/mirror path
anywhere in the file.

**What NOT to blame:** `ncc` already correlates at native pixel resolution over the FULL scene (no
resize/letterbox bottleneck -- that's a different, already-documented issue for `dino-dense`/
`owlv2` in `docs/ROBUSTNESS-BACKLOG.md`). Scene tiling is a fallback lever only, tested last if
steps 2-3 don't close the gap.

Purpose: turn an untested hypothesis into a measured verdict, ship whatever change actually earns
its keep on the floor-plan domain without touching the synthetic-regime numbers, and write up the
finding for the next reader.
Output: a (possibly empty) code change gated by measurement, a dated report section, and a clean
commit trail ready for its own PR.
</objective>
