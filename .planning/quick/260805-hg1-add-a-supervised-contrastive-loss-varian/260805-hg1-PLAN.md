<objective>
Add a **supervised-contrastive (SupCon) loss variant** to the OWLv2 floor-plans fine-tuning recipe,
train it on the `headonly` freeze arm, and measure — on the same frozen 28-plan test splits, through
the same tuning harness — whether it closes the gap that the classification-loss recipe (quick task
260801-8zy) measurably did not.

Purpose: 260801-8zy's diagnosed reason for its negative result is that the training objective (5-way
text-conditioned classification) is a poor proxy for what `owlv2-oneshot` actually does at inference
— rank scene patches by **cosine similarity** to a single image-derived query embedding. A SupCon
loss over `class_embeds` trains that exact property: same-class instances cosine-close, different-class
and **background** patches cosine-far. That is a directly-matched objective rather than a correlate,
and it is worth one measured number before concluding OWLv2 fine-tuning is a dead end on this domain.

Output: a torch-free, fully-tested NumPy SupCon reference + background-sampling module; an opt-in
`--loss-mode {focal,contrastive,both}` in the existing recipe with the default unchanged; per-epoch
cosine-gap diagnostics that carry their own pretrained reference point; one GPU arm trained,
exported, and evaluated; and a report row that states the answer plainly either way.
</objective>

<decisions>
Locked before implementation. The executor implements these; it does not re-litigate them. Each is
recorded — with its reasoning — in `src/object_search/train/supcon.py`'s module docstring.

**D-hg1-01 — SupCon formulation: L_out.**
`L = Σ_i (−1/|P(i)|) Σ_{p∈P(i)} log( exp(z_i·z_p/τ) / Σ_{a∈A(i)} exp(z_i·z_a/τ) )` with `z` L2-
normalized, `A(i)` = every other pooled embedding except `i` itself, `P(i)` ⊂ `A(i)` the same-class
anchors. Khosla et al. §3 show `L_out` ≤ `L_in` and that `L_out` is the empirically superior of the
two — the positives-inside-the-log variant is the common misimplementation.

**D-hg1-02 — temperature τ = 0.07.** The value SupCon reports its headline results with, and the
SimCLR/MoCo convention. Exposed as `supcon_temperature` on `FinetuneConfig` (`gt=0.0`) so it is in
`train_log.json` beside the numbers it produced.

**D-hg1-03 — background patches are denominator-only negatives, and this is load-bearing, not a
refinement.** `owlv2-oneshot`'s measured floor-plan failure is precision 0.01–0.11 with high recall
— background scoring too high. A SupCon over matched anchors alone only separates door-from-window;
it cannot touch door-from-background, and shipping it would repeat 260801-8zy's mistake in a new
costume. `supcon_background_negatives` (default 64 per image, `ge=0`, 0 disables and is tested)
patches per image are sampled — deterministically, from `np.random.default_rng(seed)`, never a bare
`random` call — from grid cells whose normalized centre lies in NO ground-truth box. They appear only
in the denominator: never anchors, never positives.

**D-hg1-04 — the contrastive pool is the EFFECTIVE batch: anchors and background negatives are
pooled across all `grad_accum` micro-batches and SupCon is computed once per optimizer step.**
Rationale: per fact (6), a per-micro-batch pool gives stairs zero same-class positives most of the
time, so the rare classes would contribute nothing and the loss would quietly be a door/window loss.
Pooling to the effective batch gives ~7. Cost, stated rather than hidden: in contrastive/both mode
the backward is deferred to the accumulation boundary, so `grad_accum` micro-batch graphs are
retained. In the **primary `headonly` arm this is cheap** — the ViT runs under `no_grad`, so the
retained graph is `class_head.dense0` plus the box head, not the backbone. With an unfrozen backbone
it retains `grad_accum` ViT graphs and needs a lower `--grad-accum`; that is documented in the
`--help` text and the docstring, and is a further reason the primary contrastive run is `headonly`.
Rejected alternatives: raising `--batch-size` (memory at 960×960 / 3600 patches, and it changes the
optimizer schedule so the arm stops being comparable to the existing three), and accepting sparse
rare-class positives (it silently converts a 5-class objective into a 2-class one).

**D-hg1-05 — `--loss-mode` has three values and `focal` stays the default.**
`focal` (today's behavior, byte-comparable), `contrastive` (`w_contrast * supcon` replaces
`w_class * loss_ce`), `both` (`w_class * loss_ce + w_contrast * supcon`). `both` is implemented and
smoke-tested because it is a two-line composition difference and not an inert knob, but it is **not
trained on GPU in this task** — the report says so explicitly rather than implying it was measured.

**D-hg1-06 — `val_cos_gap` is measured at epoch 0 (pre-training) as well as after every epoch.**
Without an epoch-0 measurement the cosine gap has no reference point inside the run, and re-running
the focal arms to get one is out of budget. Epoch 0 costs one extra val pass and makes the run
self-interpreting: it can distinguish "the loss moved the property the method uses but F1 did not
follow" from "the loss did not even move the property", which is precisely the question 260801-8zy
could not answer.

**D-hg1-07 — the report is EXTENDED, not forked.** `docs/reports/owlv2-floorplans-finetune.md`
already carries the verdict a reader looks for; a second file would leave a stale headline in the
first. The existing sections are appended to and the top verdict is rewritten to cover both
experiments. The already-committed classification-loss numbers are not altered.
</decisions>

    - `supcon_loss(embeddings, labels, temperature, *, negative_only)` returns a float.
      - Planted structure beats noise: embeddings clustered by label score a STRICTLY lower loss
        than the same embeddings with labels shuffled. This is the non-tautological test.
      - An anchor whose label is unique in the pool contributes zero and is excluded from the
        divisor: a pool of all-distinct labels returns 0.0 exactly, not NaN and not an exception.
      - Invariance: the value is unchanged by a permutation of the pool, and unchanged by scaling
        any embedding by a positive constant (L2 normalization is applied inside).
      - `negative_only` rows appear in the denominator and never as anchors: appending a
        `negative_only` embedding cannot decrease the loss.
      - Lower temperature increases the loss for a fixed imperfect configuration (sharper weighting).

      centre `((col+0.5)/grid, (row+0.5)/grid)` lies in NO `(cx, cy, w, h)` box.
      - A box covering the whole unit square leaves zero background cells.
      - An empty box array leaves every cell background.
