<objective>
Fine-tune OWLv2 on the Roboflow floor-plans-500 **train** split (197 images, 3962 boxes, 5
categories), export the fine-tuned weights to ONNX as a separate artifact, and re-run the existing
floor-plan evaluation harness to measure whether `owlv2-oneshot` precision/recall improve over the
shipped zero-shot baseline (door F1 0.180 tuned / 0.115 default; window F1 0.023 / 0.022).

Purpose: the floor-plan domain-shift investigation established that `owlv2-oneshot`'s ~0.01–0.11
precision on this domain is a genuine domain-fit failure of OWLv2's *pretrained embedding space*,
and two cheap mitigations (tiling, query augmentation) were tried and reverted. Fine-tuning is the
one lever that can change the embedding space itself. This settles the question with a measured
number rather than an argument.

Output: a torch-free, tested target-builder module; a self-contained fine-tuning script; a
checkpoint-parameterized ONNX export; an opt-in model-path override; a vast.ai GPU recipe; and a
committed before/after report. A negative result is a valid, reportable outcome.

Established by source inspection **this session** against the installed `export` pixi env
(`transformers==5.14.1`) in the main checkout. Treat as facts; do not re-derive.

1. `Owlv2ForObjectDetection.forward()` has **no built-in detection loss** — no `labels`
   parameter, no matcher wired in (matches the open upstream gap huggingface/transformers#33664).
   Matching + loss must be supplied by this task.
2. `transformers/loss/loss_for_object_detection.py` **exists in the installed env** and exports
   `HungarianMatcher` (line 285), `ImageLoss` (line 85), `sigmoid_focal_loss` (line 53), and
   `generalized_box_iou` (line 407). Reuse them; do not hand-write Hungarian matching or GIoU.
   huggingface/transformers#47658 (`Owlv2HungarianMatcher`/`Owlv2Loss`, unmerged) is a useful
   *reference for the wiring pattern only* — do not depend on it merging and do not vendor it.
3. **`ImageLoss.loss_labels` and `loss_cardinality` are DETR-shaped and will not work as-is.**
   Both assume a softmax head with an extra no-object logit column (`target_classes` is filled
   with `self.num_classes` as the background index, and `empty_weight` has `num_classes + 1`
   entries). OWLv2's `logits` are `[B, num_patches, num_text_queries]` with **no** background
   column. This is the one place the stock module must be overridden.
4. **The image-guided inference path this repo uses shares its weights with the text-conditioned
   training path.** Both `forward()` (line 1437) and `image_guided_detection()` (line 1337) call
   the same `self.class_predictor` / `self.box_predictor` over the same `vision_model` — exactly
   the modules `_export_owlv2`'s `_VisionGraph` exports. Text-conditioned fine-tuning therefore
   improves the exported graph with **zero** changes to `owlv2_oneshot.py`'s algorithm.
5. `Owlv2ForObjectDetection` has `box_head`, `class_head`, and `objectness_head` attributes
   (confirmed at lines 1123/1147/1181). `logit_scale`/`logit_shift` live inside `class_head`
   (lines 1056–1060), so training `class_head` also trains OWLv2's learned calibration.
6. The `export` pixi env carries `torch`, `transformers`, `numpy`, `cv2`, `pydantic`, `loguru`,
   and `PIL` — so `scripts/finetune_owlv2.py` can import `object_search.*` via the same
   `sys.path.insert(0, repo_root/"src")` bootstrap `scripts/export_owlv2.py` already uses.
7. `pixi run lint` / `typecheck` cover `src/` and `tests/` only — **not `scripts/`**. That is the
   existing precedent (`scripts/export_owlv2.py`), and it is why torch code lives in `scripts/`
   and the testable, torch-free glue lives in `src/object_search/train/`.
8. Committed split sizes: `floorplans-door` and `floorplans-window` each have **56 val / 28 test**
   plans (`dataset_splits/*.split.json`, `val_strategy: native`).
