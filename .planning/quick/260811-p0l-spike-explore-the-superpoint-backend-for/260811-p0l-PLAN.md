<objective>
Settle, with measurements on a second domain, whether the floor-plans-500 verdict "SuperPoint
loses to SIFT for `sparse-geo`" is a property of the *backend* or a property of *sparse line-art*.

Run `sparse-geo` over the 30-image `real-objects` set (10 everyday objects x plain/varied/cluttered,
real photographic texture) under five conditions — the shipped SIFT baseline, two SIFT voting-mode
controls, and SuperPoint at both frameless-compatible voting modes — through the project's own
benchmark scoring path, and write the engineering log.

Purpose: the floor-plans result was measured where SIFT and SuperPoint both nearly starve for
keypoints (4/5 exemplar crops abstained under *both* detectors) and where SuperPoint hit a hard
zero-keypoint ONNX/CoreML crash. Neither of those conditions is expected to hold on 1024px
photographs of apples and hammers. Until it is measured on rich texture, "SuperPoint is worse" is
an over-generalisation from one adversarial domain.

Output: a throwaway-grade but committed driver in `scripts/`, a raw results JSON in this quick
task's own directory, and `docs/reports/sparse-geo-real-objects-superpoint-spike.md`. **No change
to `src/`**: this is a spike, and `backend="sift"` remains the shipped default regardless of the
numbers (the MagicLeap weights are non-commercial research-only and gitignored, so SuperPoint could
not become the default even if it won).
</objective>

  `$HOME/.pixi/bin/pixi run ...` from Bash.
- `git rev-parse --show-toplevel` here is the **worktree** `.../object-search-exploration_worktrees/sharp-ford`.

- `models/` in this worktree is **empty**. `superpoint.onnx` must be fetched before anything else.
- `benchmark._run_one` hardcodes `spec.config_model()` — there is no per-method config override on
  the `bench-real-objects` Hydra path, so a plain CLI override cannot select the backend. The
  driver supplies the config by handing `_run_one` a `MethodSpec` whose `config_model` is bound.
- `MethodSpec` is a `@dataclass(frozen=True)`; `dataclasses.replace` is the supported way to make a
  variant of it.
- `SparseGeoConfig` resolves `backend="superpoint"` with no named `voting_mode` to
  `translation-2dof` automatically, and **raises at construction** for
  `superpoint` + `single-4dof`. Both voting modes must therefore be named explicitly in the sweep.
- `real_objects_image_ids()` returns 30 ids of the form `real-{plain,varied,cluttered}-{object}`;
  the regime is `image_id.split("-")[1]`. This dataset has **no val/test split** (unlike
  floor-plans-500), so there is nothing to tune on — every condition runs at method defaults with
  only `backend`/`voting_mode` pinned. Say so in the report; it is what keeps the comparison honest.
- Published baseline to reconcile against (`docs/reports/real-objects-findings.md`): `sparse-geo`
  real F1 **0.786**, AP **0.740**, PLAIN F1 **0.99**, full coverage, zero error outcomes.
- `scripts/` is outside `mypy src/` and outside `ruff check src/ tests/`, and coverage measures only
  `src/object_search` — so the driver is gate-neutral. Write it cleanly anyway; `scripts/` has
  Ruff per-file-ignores for `T201`/`ANN`/`E501` if the linter is ever pointed at it.
- Precedent for a committed experiment driver: `scripts/ncc_floorplan_experiment.py`,
