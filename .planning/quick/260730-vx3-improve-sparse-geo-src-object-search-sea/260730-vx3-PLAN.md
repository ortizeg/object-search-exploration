<objective>
Improve Method 2 (`sparse-geo`, `src/object_search/search/sparse_geo.py`) on the floor-plan
door/window target domain by testing two independent hypotheses against the measured flat-recall
symptom, keeping only what measurably helps, and shipping the engineering log
`docs/reports/sparse-geo-improvement.md`.

**The symptom** (`docs/eval/floorplans-findings.md`): sparse-geo scores doors test F1 **0.219**
(P 0.44 / R 0.15) with recall by symbol size **flat at 0.14 / 0.13 / 0.14** (small / medium /
large). Windows on the same dataset climb 0.13 -> 0.40 with size. Flatness across size is the
signature of a *structural* failure, not "too few pixels".

**Hypothesis 1 — mirror rejection.** `_is_degenerate()` (sparse_geo.py:1041) unconditionally
rejects any fitted similarity with `det < 0` as degenerate. Door symbols are routinely drawn as
genuine mirror images (same swing arc, opposite hinge hand), so a correct fit for half the doors
in a plan may be exactly the fit this gate discards.

**Hypothesis 2 — low keypoint yield on line-art.** A door symbol is a straight line plus a
quarter-circle arc: almost no DoG-style texture for SIFT. A/B the learned `backend="superpoint"`
against the SIFT default.

These are **not mutually exclusive**. Measure each in isolation first so gains are not conflated,
then combine whichever individually helped.

Purpose: this method has no improvement report yet, and it is currently 3rd on doors / 2nd on
windows — the two hypotheses are cheap, testable, and target the specific measured symptom.
Output: a measured verdict on both hypotheses (including a negative verdict, which is a real
result), whatever code change survived the revert filter, and the engineering log.
</objective>

**Step A — hypothesis 1 in isolation: mirror acceptance.**

A1. *Diagnose before you tune.* Mirror rejection at `_is_degenerate` is only the LAST place a
mirrored door can be lost. Two upstream stages can drop it first, and if either does, relaxing
`_is_degenerate` cannot possibly move the numbers:
  - **Descriptors.** SIFT descriptors are not mirror-invariant, so a mirrored door may produce no
    correspondences at all.
  - **Voting.** `_vote_single_4dof` and `_proper_similarity_2pt` compute only the
    orientation-preserving branch, so a mirrored instance's correspondences vote at a *wrong*
    pose and never accumulate into a peak — even though `_two_point_models` (used later, inside
    RANSAC) does return both the proper and the reflected fit.
Instrument this cheaply on a handful of floor plans containing mirrored door pairs: read the
existing `diagnostics.metrics` (`n_correspondences`, `n_crop_matched`, `n_peaks`, `n_instances`)
plus the `_is_degenerate` rejection reason already logged at debug level, and record where the
mirrored instances actually die. Write the finding into RESULTS.md — this diagnosis is a
deliverable whether or not it produces a win.

A2. Add `allow_mirror: bool = Field(default=False, ...)` to `SparseGeoConfig` (frozen; a
`description` written for the UI form) and thread it into `_is_degenerate`. When set, the
`det &lt; 0` branch does not reject; the scale-plausibility bound and the `min_inliers` floor are
untouched and remain the gates.

A3. *Only if step A1 shows the loss is at the voting stage*, extend mirror handling to be
end-to-end under the same single flag: cast the reflected branch as an additional pose vote in
